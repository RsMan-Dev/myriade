Contexte. `behaviours/held_swap.rs` met la créature dans son seau (`bucket_entity_data`) mais n'écrit que les données par défaut de `Bucketable.saveDefaultDataToBucketTag`. Seule la morue est juste (elle n'a rien de plus). Jar 26.3 (javap sur `animal.fish.Salmon`, `TropicalFish`, `axolotl.Axolotl`, `frog.Tadpole`) : le seau ne passe PLUS par `BucketVariantTag`, c'est le composant d'objet qui porte la variante. Cause tranchée par le jar ; non testé au banc.

Interfaces (chaque ligne est un fait du jar, relis-le avec `javap -p -c` sur la classe nommée avant de coder, ne pars pas de cette liste seule) :

Lis la classe `Salmon$Variant` (ou celle du composant) pour le nom sérialisé exact (small, medium, large attendus) et la valeur (chaîne).
2. `TropicalFish.saveToBucketTag` : défaut, puis `copyFrom` de `TROPICAL_FISH_PATTERN`, `TROPICAL_FISH_BASE_COLOR`, `TROPICAL_FISH_PATTERN_COLOR` : composants `minecraft:tropical_fish/pattern` (nom du motif : kob, sunstreak, snooper, dasher, brinely, spotty, flopper, stripey, glitter, blockfish, betty, clayfish), `.../base_color` et `.../pattern_color` (noms de teinte : white…black). Le motif et les teintes se décodent de l'identifiant empaqueté `Wide` : motif = bits 0-15 (taille dans l'octet bas, indice << 8), base = bits 16-23, motif-couleur = bits 24-31. Lis `TropicalFish$Pattern` dans le jar pour l'ordre des noms ; l'indice des teintes est l'ordre de `DyeColor`.
